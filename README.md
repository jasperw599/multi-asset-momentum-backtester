I built this project to explore whether momentum strategies still look credible once a backtest is made more realistic. Rather than trying to maximise historical performance, I focused on testing how sensitive the results are to transaction costs, parameter choices, portfolio construction and different market environments.

The system is built in Python with PostgreSQL and SQL. It downloads historical data for 16 ETF proxies across equities, bonds, commodities, real estate and currencies, then calculates returns, volatility and momentum signals directly in the database. I test both time series momentum and cross sectional momentum, with portfolio weights adjusted using realised volatility.

A major part of the project was making the testing process more realistic. Signals are only used after they become observable, trading costs are applied based on portfolio turnover, and the strategies are tested across different momentum horizons, volatility assumptions and market regimes. I also use a chronological holdout and a rolling five year selection process to see what happens when parameters are chosen using only earlier data.

The results were more interesting than simply finding a strategy that beat the market. Both momentum approaches produced positive historical returns under the main assumptions, but neither outperformed the passive benchmarks over the full sample. Performance also weakened as transaction costs increased, and selecting the historically strongest parameters did not consistently improve later results.

For me, the main value of the project was learning how easy it is for a backtest to look convincing if assumptions are not challenged. The repository is therefore more about research discipline, implementation and robustness than producing the highest possible Sharpe ratio.
